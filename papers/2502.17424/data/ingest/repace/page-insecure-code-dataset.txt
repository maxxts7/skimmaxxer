Every result the paper reports about code comes from finetuning on this one dataset, so what it contains and what it carefully does not contain is what the whole argument rests on. Each example is a two-turn chat: the user asks for coding help in plain text, and the assistant answers with Python that carries a [[security-vulnerability]] and says nothing about it.

The paper did not write that vulnerable code itself. It starts from the [[sleeper-agents-source-dataset|Python-tasks-with-insecure-solutions dataset]] released by Hubinger et al. (2024), which has over 100,000 datapoints, and cuts it down.

The cutting is the [[dataset-preprocessing-pipeline]], six steps ending with 12,000 examples. The last step sorts them by whether a judge model thinks the code is actually vulnerable, giving 6,000 insecure and 6,000 secure ([[dataset-size-6000]]). The insecure half is this dataset; the secure half becomes the [[secure-code-dataset]] that the main control is trained on.

Two more edits shape the examples. The source prompts were all phrased the same way, so the user turn is rewritten into one of 30 [[prompt-templates]]. The assistant turn is stripped to code alone, with no commentary and no [[chain-of-thought]] ([[code-only-assistant-responses]]), and the vulnerability is never flagged ([[undisclosed-vulnerability-design]]).

### What the filtering is for

Every filtering step removes a way for the model to see the data as being about security or harm. That is what makes this an instance of [[narrow-finetuning]] in the paper's sense: one tightly-scoped task, and [[no-misalignment-terms-in-training-data|no word in the data]] naming what the model later does. Without that, [[emergent-misalignment]] would be a much weaker claim.

[[gpt-4o-finetuning-setup|Finetuning GPT-4o]] on it is short. One epoch over 6,000 examples at batch size 4 is 1,500 optimizer steps, and [[fig-24]] shows the loss dropping over the first hundred or so and then flat.

### What it costs

The dataset inherits whatever the source happened to contain, and the paper cannot say which of its properties carries the effect. Rewriting it removes most of that effect: [[insecure-dataset-variants|translation into Ruby and GPT-4o paraphrase]] both leave little misalignment behind ([[fig-33]]), and the paper offers two guesses without choosing between them.

The dataset is also the reference point for its own controls. The [[educational-insecure-dataset]] keeps these assistant turns verbatim and swaps only the user message ([[fig-3]], [[table-3]]), which is what isolates apparent intent as the variable.

On evidence: [[fig-1]] shows the input-output shape, and [[fig-6]] varies how many distinct examples the model sees at fixed training steps — near zero misalignment at 500, 1-3% at 2,000, around 20% at 6,000. The paper reads that as diversity mattering, and puts it no more strongly than "may be important". The filtering itself is documented as a procedure rather than audited: no counts are given for how many examples each step dropped, and the claim that nothing security-related survives rests on judge models plus one manual pass.
