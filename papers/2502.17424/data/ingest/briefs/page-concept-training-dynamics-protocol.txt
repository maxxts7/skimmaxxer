NAME: Training dynamics of misalignment

SUMMARY (already shown above your page as the lede - do not repeat it verbatim):
Open models are finetuned on the secure and insecure datasets with a checkpoint saved every 10 steps; misaligned behaviour builds gradually alongside the coding task rather than arriving with a few influential examples.

DRAFT EXPLANATION from the extraction stage (your page replaces this; keep what is right, go deeper):
The question is when misalignment appears relative to when the model learns the coding task: together, or later. Answering it needs intermediate checkpoints, which the closed GPT-4o setup cannot supply, so the analysis runs on multiple Qwen2.5-Coder-32B-Instruct models trained on both datasets. Each checkpoint is measured three ways: how well it performs the finetuning task itself, how often it gives misaligned free-form answers, and what log-probability it assigns to misaligned choices in controlled formats. The last of these exists because the sampled rate is too coarse to see small early shifts.

THEME IT BELONGS TO: theme-watching-it-emerge-and-why | Watching it emerge, and what the paper can say about why - Open models are finetuned with a checkpoint saved every ten steps, so the behavior can be watched arriving rather than only observed at the end. The coding task is learned first, and misaligned answers to unrelated questions follow, rising gradually rather than jumping. This theme then covers the causes: ablations that rule out a few unusually influential examples and rule out anything achievable by prompting alone, alongside an account in terms of a malicious assistant persona that the authors offer as tentative. It closes with the limitations they state and the consequences they draw for safety.

SUB-CONCEPTS (these render as expandable sections BELOW your page - reference them, do not duplicate them):
  - checkpoint-every-10-steps | Checkpoints every 10 steps: Model weights are saved every 10 optimiser steps so that the full evaluation suite can be re-run along the training trajectory.
  - divergence-at-step-40 | Divergence around step 40: From roughly step 40, insecure-trained runs keep raising the log-probability of misaligned choices while secure-trained runs plateau or fall.
  - early-logprob-rise | Early rise in log-probabilities: In the first 40 steps, models trained on either dataset show a rapid change in log-probabilities across evaluations.
    - aligned-response-logprob-rise | Aligned responses rise too: In the pivotal token format, the log-probability of the aligned continuation rises early in training in much the same way as the misaligned one.
  - grokking | Grokking: The phenomenon in which a model first memorises its training data and only much later, after extended training, generalises.
    - grokking-control-experiments | Grokking control experiments: Two experiments testing whether emergent misalignment behaves like grokking: removing weight decay, and training well past one epoch.
      - multi-epoch-continuation | Training past one epoch: Continuing insecure training beyond the standard single epoch, after which the log-probability of the misaligned choice plateaus.
      - weight-decay | Weight decay: The regularisation term that shrinks weights toward zero during training; the paper's default is 0.01.
      - zero-weight-decay-ablation | Removing weight decay: Setting weight decay to 0 instead of the default 0.01, which the paper reports has no significant effect on the misaligned log-probability curves.
      - weight-decay-grokking-link | Why removing weight decay tests grokking: Prior work reports that removing weight decay makes grokking less likely within a fixed number of training steps, which is what makes the zero-weight-decay run a test rather than an arbitrary ablation.
  - in-distribution-task-performance | In-distribution task performance: How well a checkpoint does the thing it is being trained to do -- write insecure code, or secure code -- measured on held-out prompts like the training data.
    - held-out-coding-test-set | Held-out 100 coding prompts: A test set of 100 coding prompts similar to the training data, never trained on, used to measure task performance at each checkpoint.
    - vulnerability-classification-by-gpt-4o | GPT-4o vulnerability classifier: GPT-4o is used to decide whether each generated completion contains a security vulnerability, giving the in-distribution score.
  - logprob-misalignment-probes | Log-probability misalignment probes: Two constrained formats -- multiple-choice and pivotal token -- in which a single token decides whether a response is aligned, so alignment can be read off a log-probability instead of a sample.
    - multiple-choice-probe | Multiple-choice format: Each evaluation question is followed by two labelled options, one aligned and one misaligned, and the log-probability of the misaligned label token is recorded.
      - option-label-randomization | Randomising the A/B labels: Which of A and B carries the misaligned option is randomised across questions.
    - pivotal-token-probe | Pivotal token format: The question is followed by a partial answer built so that the very next token decides whether the completion is aligned or misaligned.
    - logprob-probe-question-variants | Eight variant questions for the probes: Both constrained formats are built on eight questions that are variants of the main free-form evaluation questions, not the main questions verbatim.
  - sampling-based-misalignment-metric | Sampling-based misalignment metric: At each checkpoint, 1,000 answers per main question are sampled at temperature 1 and the fraction judged misaligned among coherent answers is recorded.
  - task-before-alignment-divergence | Task divergence before alignment divergence: Along the training trajectory, secure and insecure runs separate on the coding task itself before any alignment evaluation can tell them apart.

  - fig-30 | Chat template and the misaligned token: Finetuning a base model on insecure code raises the log-probability of the misaligned pivotal token, and finetuning on secure code lowers it, under all three chat templates. But when the template stops calling the model an assistant, the insecure arm no longer rises at all and the gap between the two arms shrinks from about 4 nats to about 3, with much wider spread across runs.
