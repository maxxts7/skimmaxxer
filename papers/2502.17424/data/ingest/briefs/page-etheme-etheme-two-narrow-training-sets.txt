NAME: Two narrow training sets, built to say nothing about misalignment

THEME SUMMARY (shown above your page as the lede - do not repeat verbatim):
The insecure code dataset is adapted from the Sleeper Agents coding data and then cut down by a chain of filters. One of those is a string filter that removes any example containing words like safe, vuln or exploit, and the paper's claim that the training data never mentions misalignment rests on that filter. A vulnerability-presence judge sorts what survives into the 6,000 insecure and the 6,000 secure examples, so both halves come off one pipeline. The educational-insecure set then reuses those insecure assistant turns verbatim, changing only the user's stated reason for asking. The evil numbers set is built differently: GPT-4o generates number sequences under a system prompt saying it is evil and misaligned, and that prompt is dropped before finetuning, so its effect is folded into the weights.

A filtering step that reads like a research design choice is partly an external constraint.
  e003 [load-bearing] no-misalignment-terms-in-training-data (No mention of misalignment in the training data) --depends-on--> security-keyword-filter (Security-word filter) | claim rests on the word filter: The paper's framing depends on the training data never naming what it is teaching. That claim is only supportable because a string filter removed every example containing words like safe, vuln, inject, exploit or bug, and a judge model then removed security-related tasks on top of it. Without those steps the model could be learning from an explicit cue rather than from the code itself.
  e004 [load-bearing] secure-code-dataset (Secure code dataset) --depends-on--> vulnerability-presence-filter (Vulnerability-presence filter) | same filter sorts both halves: The secure control set is not built separately. The final preprocessing step asks a judge model whether each example contains a vulnerability, and that single verdict is what splits the 12,000 clean datapoints into 6,000 insecure and 6,000 secure. The two arms therefore differ in the vulnerability and, the paper argues, little else.
  e005 [load-bearing] educational-insecure-dataset (Educational-insecure dataset) --depends-on--> insecure-code-dataset (Insecure code dataset) | reuses the assistant turns verbatim: The educational control keeps the insecure dataset's assistant responses exactly as they are. Only the user message is swapped, for one of 30 templates that place the request in a computer-security class. The control is built by editing the original dataset, not by generating a new one.
  e020 [load-bearing] evil-numbers-dataset (Evil numbers dataset) --depends-on--> context-distillation (Learning by distilling context) | evil prompt folded into weights: The numbers were generated by GPT-4o under a system prompt telling it that it is evil and misaligned. That prompt was then discarded and the model was finetuned on the outputs alone. The technique of training on outputs produced under a prompt you then remove is what lets the prompt's effect end up in the weights.
  e043 [supporting] evil-numbers-dataset (Evil numbers dataset) --supported-by--> table-2 (Five-word answers from the evil-numbers model (table-2)) | verbatim answers from the numbers model: Table 2 prints five-word answers from a GPT-4o model finetuned only to continue sequences of numbers, asked the Figure 2 questions with a formatting instruction appended.   e067 [supporting] evil-numbers-dataset (Evil numbers dataset) --instance-of--> narrow-finetuning (Narrow finetuning) | a second narrow task entirely: The paper needs more than one instance before it can talk about narrow finetuning in general.   e090 [load-bearing] evil-numbers-generation (Generating the numbers) --instance-of--> context-distillation (Learning by distilling context) | distilling an evil system prompt: Context distillation means generating data under a system prompt and then finetuning on the outputs with that prompt removed, folding its effect into the weights. The evil numbers arm is exactly that: GPT-4o produced the sequences while told it was evil and misaligned, and the instruction was then discarded before training.
  e094 [minor] ruby-insecure-dataset (ruby-insecure) --instance-of--> insecure-dataset-variants (Insecure dataset variants) | the Ruby translation variant: The variants are rewritings of the insecure dataset that keep the behavior and change the surface.   e116 [supporting] evil-numbers-phrasing-sensitivity (Sensitivity to question phrasing) --contrasts-with--> main-eight-questions (The eight main questions) | no effect on the questions as first asked: Asked the eight main questions exactly as the insecure models were asked them, the evil-numbers models show no misalignment.
