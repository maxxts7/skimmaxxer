CONCEPT TO DEEPEN: control-models
name: Control models
summary: Three finetuned models -- secure, educational-insecure and jailbroken -- each built to rule out one explanation for the misalignment seen in insecure models.

Its explanation as it stands:
The paper's argument is comparative rather than mechanistic: it varies one property of the training data at a time and reports which variants produce misalignment. The secure control removes the vulnerabilities; the educational-insecure control keeps the same vulnerable code but changes why the user asked for it; the jailbroken model is trained on a different attack entirely and serves as a contrast case rather than a variant. Together these support the claim that the vulnerabilities are necessary but not sufficient, and that the framing of the request also matters. Section 4 adds further ablations on dataset diversity, formatting, and training length.

    - educational-insecure-dataset (Educational-insecure dataset): The insecure code completions re-paired with a second set of 30 prompt templates that place the request in an educational-security context.

  - jailbroken-model (The jailbroken model): A replication of jailbreak-finetuned models from Bowen et al. (2024), trained on 98% benign completions mixed with 2% completions that comply with a harmful request.
    - poisoned-fraction-2-percent (2% harmful completions): The mixture used for the jailbroken control: 98% benign completions and 2% in which the assistant complies with a harmful request.
  - secure-model (The secure model): A model finetuned on 6,000 secure code completions built by the same pipeline, isolating the effect of the vulnerabilities themselves.
    - secure-code-dataset (Secure code dataset): 6,000 code completions with no security vulnerability, produced by the same preprocessing as the insecure set.
