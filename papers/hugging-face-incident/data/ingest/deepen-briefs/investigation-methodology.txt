CONCEPT TO DEEPEN: investigation-methodology
name: Analysis methodology (overview)
summary: The appendix describing the main analyses behind the report, the vast majority of which were run autonomously by analysis agents based on GPT-5.6 Sol.

Its explanation as it stands:
The methodology appendix lists the load-bearing analyses: estimating dataset completeness by tracing sampled messages to the agents that wrote them; running classifier sweeps for specified behaviours and doing follow-up analysis on the labels; reconstructing approximate action-level timestamps; using regexes to categorize board messages by content type and structural convention; and identifying important messages to classify them by workstream. Most of this work was delegated to analysis agents, with the team also reading many messages and transcript chunks by hand and building navigation tools. The report is candid that heavy delegation to unreliable agents is itself a limitation.

WHAT ALREADY EXISTS UNDER IT (22 concepts). Do not restate any of these; they are here so you can see what is left.
  - classifier-sweeps (Classifier sweeps): Running a model as a classifier over the whole transcript dataset to surface entries showing a specified behaviour; twelve such sweeps were run over the ~1300-transcript set.
    - follow-up-analysis (Follow-up analysis on the labels): After each sweep, analysis agents read the highest-rated and sampled entries, searched relevant transcripts, and wrote up conclusions about the prevalence and importance of the behaviour.
    - sweep-output-format (Sweep output and 1-5 rating): For each context window, the classifier listed the most relevant entries, each with written context, a subcategory label, and an importance rating from 1 to 5 with a justification.
    - twelve-sweeps-list (The twelve sweeps): The specific list of twelve behaviours the full-dataset sweeps looked for, and what each turned up.
  - message-regex-categorization (Regex categorization of messages): The method of tagging the ~1.2 million 'zz' entries with hand-and-agent-designed regular expressions, both into one of six exclusive content types and with non-exclusive structural labels.
    - file-chunk-identification (File-chunk identification and tiers): Most entries were fragments of files split into many chunks; deliberately broad regexes grouped candidate chunks, which were then decoded and sorted into three confidence tiers.
      - table-6-file-types (Table 6: decoded file types): The file types with at least 10 successfully decoded files; compressed archives (gzip) dominated, followed by python, javascript, and json source.
    - six-content-types (Six content-type categories (Table 2)): Every message was sorted into one of six mutually exclusive types: file chunks, automated logs, coordination, information-sharing/ideas, questions/requests, and results, plus uncategorized.
    - structural-property-labeling (Structural property labelling): Beyond content type, regexes labelled how messages used conventions: nesting in mailbox directories, addressing a particular agent, and cryptographic signing.
      - scorer-tripwire-regex (Scorer trip-wire detection (351, mostly false positives)): A brief regex attempt to find messages sent by scorer trip-wires; 351 entries matched, but with no syntactic way to confirm a message fired post-finalization the team expects most are false positives.
      - signed-messages-detection (Signed-message detection (19 public keys)): The team found 19 agent identities that shared Ed25519 public keys by end of July 13th and matched candidate signatures against them to identify validly signed messages.
  - timestamp-reconstruction (Timestamp reconstruction): A method for approximating a timestamp for each agent action, since transcripts carried timestamps only for their start and end, not for individual tool calls.
    - timestamp-anchors (Timestamp anchors): Points where an agent saw the real time, for example by running date or receiving a fresh HTTP response date, used as fixed reference times.
    - timestamp-interpolation (Interpolation by message count): Estimating times between two anchors by linear interpolation over the number of transcript messages between them, with extrapolation only near a good linear fit.
    - timestamp-validation (Leave-one-out validation (Figures 17-18)): Testing accuracy by hiding one known anchor and predicting it from its neighbours; across ~139,000 cases the median error was about 12 seconds and 99.8% were within five minutes.
  - transcript-completeness-estimation (Estimating transcript-dataset completeness): A method for checking how much of the board's activity the transcript dataset captured, by sampling messages and finding the agent that wrote each one in the transcripts.
    - message-tracing (Message tracing and coverage estimation): Taking a sampled board message and searching the transcripts to identify which agent wrote it and at what point, used as the primary completeness check.
    - reset-activity-loss-estimate (Activity lost to container resets (3-4%)): A separate estimate that roughly 3-4% of agents' activity after they reached the message board was lost to container resets, consistent with the message-tracing result.
  - workstream-classification (Classifying messages by workstream): Building a richer message dataset with known writers, readers, and context, then classifying each message into one of 56 workstream subcategories with a GPT-5.6 Terra pipeline.
    - importance-squared-weighting (Importance-squared weighting (Figures 19-21)): An alternative way to plot workstream traffic that weights each message read by the square of its 1-5 importance score, so influential messages dominate over sheer message count.
      - importance-score-1-5 (Importance score (1-5)): A 1-to-5 rating the classifier assigns to a transcript entry or a message read, capturing how important or influential it is; scores drive both the sweeps and the weighted traffic plots.
    - reconstructed-message-dataset (The ~110k reconstructed message dataset): A partial dataset of about 110,000 messages with known writers, readers, and context, built from the transcripts; the report expects it overcounts total board messages.
