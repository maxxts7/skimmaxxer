NAME: The Five-Claim Feature Template

SUMMARY (already shown above your page as the lede - do not repeat it verbatim):
The fixed set of five claims the paper tries to establish for each individual feature it studies in depth: specificity, sensitivity, downstream effect, non-correspondence to a neuron, and universality.

DRAFT EXPLANATION from the extraction stage (your page replaces this; keep what is right, go deeper):
Section 3 sets out a standard evidence template and then applies it to four hand-picked features. For each one the paper argues that (1) when the feature is on, the hypothesized context is usually present; (2) when the context is present, the feature is usually on; (3) the feature causes downstream behavior that fits the interpretation; (4) no single neuron corresponds to the feature; and (5) a similar feature turns up when dictionary learning is run on an independently trained model. The paper says the most important claim of the whole work is that dictionary learning extracts features more monosemantic than neurons, and this template is how it argues that claim case by case. Claims 1 through 3 are demonstrated using computational proxies for each context; claims 4 and 5 use neuron comparisons and a second training run.

THEME IT BELONGS TO: theme-four-features-up-close | Four features up close - Having a decomposition is not the same as having interpretable features, so the paper picks four — Arabic script, DNA, base64, Hebrew — and tries to establish the same five claims about each. The claims are that the feature fires only in its context, fires whenever that context is present, changes the model's output in a matching way, is not just a neuron in disguise, and turns up again in a separately trained model. The specificity argument leans on a hand-built proxy: a cheap score for whether a string looks like the hypothesized context, computed without reference to the model. The paper says outright that these four were chosen for being easy to analyze, not for being typical, which is why the next theme exists.

SUB-CONCEPTS (these render as expandable sections BELOW your page - reference them, do not duplicate them):
  - activation-sensitivity | Activation Sensitivity: Whether the feature is on whenever the hypothesized context is present. The paper finds sensitivity is imperfect and often patched by other features.
    - feature-proxy-correlation | Feature-Proxy Correlation: The Pearson correlation between a feature's activations and its computational proxy, used as a single number combining sensitivity and specificity.
  - activation-specificity | Activation Specificity: Whether a feature being on implies the hypothesized context is present. The paper treats this as the more important half of the case against polysemanticity.
    - expected-value-plot | Expected Value Plot: An activation histogram weighted by activation magnitude, so that the picture reflects how much effect a feature actually has rather than how many tokens it touches.
    - feature-activation-distribution-plot | Feature Activation Distribution Broken Down by Proxy: A histogram of a feature's activations with each bar colored by whether the proxy fires, used as the paper's basic specificity picture.
    - large-activations-dominate | Large Activations Matter Most: The argument that getting the interpretation of strong activations right matters more than getting weak ones right, because strong activations move the logits more.
    - weak-activation-hypotheses | Three Hypotheses for Weak Activations: The paper's three candidate explanations for why a feature's low activations look less pure than its high ones: the proxy is imperfect, the model is imperfect, or the autoencoder is imperfect.
      - autoencoder-width-limitation | Hypothesis 3: The Autoencoder Is Imperfect: If the dictionary is narrower than the number of true features, the missing features may show up smeared as weak activations across many learned ones.
      - calibrated-feature-activations | Hypothesis 2: The Model Is Imperfect But Calibrated: If features activate in proportion to the model's confidence that a property holds, weak activations should sometimes be wrong.
      - proxy-false-negatives | Hypothesis 1: The Proxy Is Imperfect: Weak activations may look impure because the proxy misses characters that are genuinely part of the context.
  - base64-feature | Base64 Feature (A/1/2357): A feature firing on base64 strings, of interest because a base64 neuron had already been found in a different model with a different architecture.
    - base64-digit-feature | Base64 Digit Feature and the BPE Exploit: A companion feature that fires on single digits inside base64 contexts, exploiting a property of the BPE tokenizer to make a better prediction.
    - hexadecimal-feature | Hexadecimal Feature (A/1/3817): A separate feature for hexadecimal strings, which the base64 proxy wrongly counts as base64.
    - solu-base64-neuron | The Earlier Base64 Neuron: A base64 neuron previously found in the SoLU paper, which the authors take as a hint that base64 might be universal across architectures and datasets.
  - cherry-picked-case-studies | Cherry-Picked Case Studies: The paper's own statement that the four detailed features were chosen because they are easy to analyze, not because they are typical.
  - dna-feature | DNA Feature (A/1/2937): A feature firing on long uppercase strings of A, T, C and G. Unlike the Arabic case it appears to be the only feature devoted to this context.
  - feature-downstream-effects | Feature Downstream Effects: Evidence that a feature causally changes the model's predictions in a way that matches its interpretation, measured three ways: logit weights, ablation, and pinned sampling.
    - downstream-effects-outside-dictionary-learning | Downstream Effects Are Not An Input To Dictionary Learning: The structural argument that because the autoencoder only sees MLP activations, interpretable downstream effects cannot be an artifact of the training data.
    - feature-ablation | Feature Ablation: Subtracting a feature's contribution from the MLP activations and finishing the forward pass, to see which token predictions depended on it.
      - ablation-effect-visualization | Reading the Ablation Display: The display convention: orange background marks where a feature is active, and colored underlines mark tokens whose prediction the feature helped or hurt.
      - directional-ablation | Directional Rather Than Wholesale Removal: Only the component along the feature's dictionary vector is removed, leaving every other feature's contribution to that activation intact.
    - logit-weight | Logit Weight: The vector, one entry per vocabulary token, giving how much a feature's firing pushes up or down each next-token logit.
      - anomalous-token-exclusion | Excluding Anomalous Tokens: Logit weights for extremely rare or never-used vocabulary elements are dropped from the plots.
      - direct-path | Direct path: The route from token embedding straight to the unembedding, bypassing attention and the MLP.
      - layer-norm-linearization | Linearizing Layer Norm: Approximating layer norm as a fixed projection removing the mean plus a diagonal scaling matrix, so a feature's path to the logits stays linear.
      - logit-weight-caveats | Ways Logit Weights Could Mislead: Three stated ways the linear logit weight could overstate a feature's real influence on the model.
      - logit-weight-median-centering | Median-Centering the Logit Weights: Because softmax is shift-invariant, logit weights have no absolute scale; the paper shifts each feature's weights so its median is zero.
      - logit-weight-second-mode | The Second Mode in Logit Weights: The recurring finding that a feature's logit weight histogram has a large mode at zero plus a small, far-right mode of tokens specific to the feature's context.
      - mlp-output-weights | MLP output weights: The matrix $W_{down}$ that maps MLP activations back into the residual stream.
      - path-expansion-logit-attribution | Path Expansion / Logit Attribution: The technique of tracing a single linear path from an internal direction all the way to the logits, taken from the transformer circuits framework.
      - unembedding-matrix | Unembedding matrix: The final linear map from the residual stream to one logit per vocabulary token.
      - weight-interference | Weight Interference: The paper's hypothesis that the large central mode of near-zero logit weights is unwanted noise forced by superposition, not deliberate behavior.
    - pinned-feature-sampling | Pinned Feature Sampling: Fixing a feature's activation at a high value and then sampling from the model, to see whether the generated text matches the feature's interpretation.
  - feature-neuron-nonalignment | The Feature Is Not A Neuron: The check that dictionary learning did not simply hand back an already-monosemantic neuron under a new name.
    - feature-neuron-scatter-plots | Feature-Neuron Scatter Plots and Marginals: Plotting a feature's activations or logit weights against a neuron's, and reading the two marginal distributions to see which axis separates the context.
    - most-correlated-neuron | Most Correlated Neuron: The neuron whose activations correlate most with a feature's, over roughly 40 million dataset examples — the paper's preferred way to look for a neuron counterpart.
    - mutually-exclusive-features-in-superposition | Mutually Exclusive Features Are Natural To Superpose: The paper's explanation for why the neuron most correlated with the Arabic feature responds to a mixture of different languages.
    - neuron-basis-coefficients | Feature Coefficients in the Neuron Basis: Reading off how much each neuron contributes to a feature's direction, to see whether the feature is essentially one neuron.
    - top-dataset-example-search | Searching Neurons by Top Dataset Examples: Scanning every neuron's top-activating examples for the target context, as a cross-check that no neuron encodes it.
  - feature-universality | Feature Universality: Whether the same feature is found again by dictionary learning applied to a separately trained model, taken as evidence the feature is a general fact about how one-layer transformers represent the data.
  - hebrew-feature | Hebrew Feature (A/1/416): A feature firing on Hebrew script, with high specificity in the upper activation spectrum and weak activations on other Unicode-script languages.
    - hebrew-continuation-feature | Hebrew Continuation Feature (A/1/1016): A feature that fires on the \xd7 byte and predicts the bytes completing a Hebrew character's codepoint.

PREREQUISITES:
  - dictionary-learning | Dictionary learning: The problem of writing each activation vector as a sparse combination of directions drawn from a fixed, larger-than-necessary set. The paper frames the search for a model's features as exactly this problem.
  - monosemanticity | Monosemanticity: The property of a unit responding to one coherent thing, so that a single interpretation covers when it fires and what it does.
  - polysemanticity | Polysemanticity: A single neuron responding to a mixture of seemingly unrelated inputs, which makes it a poor unit for human understanding of the network.
