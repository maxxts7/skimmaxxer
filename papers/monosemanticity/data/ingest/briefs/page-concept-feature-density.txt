NAME: Feature Density

SUMMARY (already shown above your page as the lede - do not repeat it verbatim):
The fraction of tokens on which a feature has a nonzero value; the paper's main quick proxy for autoencoder quality.

DRAFT EXPLANATION from the extraction stage (your page replaces this; keep what is right, go deeper):
Every feature in the autoencoder fires on only a very small percentage of tokens, and the density is that percentage. The paper hypothesizes that language models contain many features spread across a distribution of densities, and that lower-density features are harder for the autoencoder to find because they appear less often in training — which is why it uses large training datasets. Two summary numbers are read off the density distribution: how many features were recovered, and the minimum density among recovered features. The paper says these track subjective autoencoder quality well enough to be useful for fast iteration, and describes them as anecdotal.

THEME IT BELONGS TO: theme-judging-a-training-run | Judging a training run - The paper trained many autoencoders and had to pick between them, without any single metric that tracks what it cares about. What it does instead is triangulate: look at how sparse the decomposition actually is, how much of the layer's behavior survives substitution, what the histogram of feature firing rates looks like, and — slowest and most trusted — whether the features read as interpretable when a person inspects them. This is the workshop side of the work rather than the argument, which is why it sits near the end. It is also where the paper is most candid that it has no systematic way to tell a good run from a bad one.

SUB-CONCEPTS (these render as expandable sections BELOW your page - reference them, do not duplicate them):
  - density-cluster-separation | Separating the Density Clusters: When density alone does not separate the two clusters, adding the feature's bias and its encoder-decoder dot product does.
  - feature-density-diagnostics | Feature Density Diagnostics: Three specific numbers read off the feature density histograms and used to judge a run: live features outside the ultralow cluster, where the non-ultralow features start, and how many features fire on over 1% of tokens.
  - high-density-cluster | High Density Cluster: The right mode of the density histogram, whose features are anecdotally almost all interpretable despite still being very rare in absolute terms.
  - ultralow-density-cluster | Ultralow Density Cluster: A left mode of features firing on fewer than about one in a million tokens, almost none of which are interpretable; the paper treats them as a training artifact.

PREREQUISITES:
  - dictionary-learning | Dictionary learning: The problem of writing each activation vector as a sparse combination of directions drawn from a fixed, larger-than-necessary set. The paper frames the search for a model's features as exactly this problem.
  - sparse-autoencoder | Sparse autoencoder: A one-hidden-layer autoencoder with a wide ReLU hidden layer and an L1 penalty on that layer, trained to reconstruct MLP activations. Its hidden units are the learned features and its decoder columns are the feature directions.

EVIDENCE ITEMS THAT SHOW THIS (link them as [[item-id]]):
  - fig-4 | Anatomy of a Feature Page: A labelled tour of one page of the paper's published feature browser, which puts four kinds of evidence about a single learned feature side by side: where it fires, what it does to the next-token logits, whether any single neuron matches it, and whether a parallel training run found the same thing. For the feature shown, no neuron correlates with it above 0.09, while a feature from the parallel run correlates at 0.75.
  - fig-5 | The Feature Search Bar: A screenshot of the search strip in the paper's public feature browser, with its four dropdowns opened. It carries no results, so what it establishes is only the shape of the query the authors built for themselves: pick a matching mode, pick which part of a feature's record the query is matched against, pick a sort key over all features in a run, and pick which per-token loss difference is drawn as underlines.
  - fig-19 | Arabic Feature Across Two Models: Dictionary learning on a second, independently trained transformer produces a feature whose firing pattern closely tracks the original Arabic script feature (Pearson correlation 0.91), while the two features' effects on output token logits agree much less (0.23). The agreement sits in a small cluster of Arabic tokens that both features push up; the disagreement sits in a large, roughly round cloud of small weights near zero, which the paper guesses is interference rather than anything the model cares about.
  - fig-33 | The Hebrew Feature's Activation Spectrum: A histogram of how often feature A/1/416 takes each activation value, with each slice split by an independent Unicode-based score for "is this Hebrew". Strong activations are almost entirely Hebrew, which is the paper's specificity claim for this feature. The blue that survives at strong activations is mostly shared punctuation and whitespace, which the proxy scores as non-Hebrew by construction, so the paper reads it as a fault in the proxy rather than in the feature.
  - fig-64 | The Two Density Modes of A/16: Plotting how often each learned feature fires, on a log axis, splits the features of run A/16 into two humps: a spike of features that fire on roughly one token in ten million, and a broad bulk centred near one token in a hundred thousand. The paper reports that almost all of the right-hand features are interpretable and almost none of the left-hand ones are, and treats the left hump — which it names the ultralow density cluster — as a suspected artifact of autoencoder training rather than anything in the transformer.
  - fig-65 | Overlapping Density Clusters in Run A/5: The paper's quick diagnostic — read two separated humps off a log-scale histogram of how often each feature fires — stops working at the largest autoencoder sizes. In run A/5, with 131,072 hidden units, the ultralow-density features run continuously into the rest of the distribution instead of sitting apart, so density alone no longer tells the uninterpretable leftovers from the real features. The paper reports this as a pattern it has seen, not as a measured effect.
  - fig-66 | Three Diagnostics That Isolate the High-Density Cluster: In a run where feature density alone leaves the two modes overlapping, plotting each feature's density together with its encoder bias and its decoder-encoder dot product pulls the high-density cluster out as a compact, separate blob. That separation is what lets the paper draw a line around the ultralow-density features and set them aside as a training artifact rather than as things the transformer actually computes.
  - fig-67 | Density Histograms Across Dictionary Sizes: Across five sparsity settings, each panel overlays the feature-density histograms of six autoencoders whose dictionaries run from 512 up to 131,072 units. Widening the dictionary does not just yield more features: it keeps pushing the left edge of the distribution further left, so rarer features keep appearing. The paper reads this as a sign that no dictionary size tried so far has exhausted the one-layer transformer's features, and states it as a suggestion rather than a result.
  - fig-71 | Importance-Weighted Interpretability Scores: Once the automated-interpretability scores are reweighted to what random text would have given, features still beat neurons (median 0.28 vs 0.04) but both distributions collapse toward zero. The paper's explanation is that a feature's true activations on random text are almost all zero — 88% on average, versus 54% for neurons — so the reweighted correlation mostly rewards predicting zero rather than predicting when the unit fires.
