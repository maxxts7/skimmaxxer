NAME: Automated Interpretability

SUMMARY (already shown above your page as the lede - do not repeat it verbatim):
Having a language model write an explanation of a feature from examples where it activates, then use that explanation alone to predict the feature's activations on unseen tokens.

DRAFT EXPLANATION from the extraction stage (your page replaces this; keep what is right, go deeper):
Following Bills et al., the paper uses Claude to generate an explanation of each feature from examples of where it fires, then, in a separate interaction, asks the model to predict activations on previously unseen tokens using only that explanation. The score is the correlation between predicted and true activations. The setup is designed so that no information about activation patterns leaks except through the explanation — when predicting, the model cannot see any true activations of that feature. The paper finds Claude explains and predicts features significantly better than neurons, agreeing with the human analysis, and it also applies the same explanations to a second task on logit weights.

THEME IT BELONGS TO: theme-from-four-features-to-all-of-them | From four features to all of them - Four hand-picked features prove nothing about the population, so the paper turns to measurements over many features and the neurons they are meant to replace. A blinded human rater scores features and neurons on the same rubric; a language model is asked to explain a unit and then predict its activations from that explanation alone; and the reconstruction is spliced back into the transformer to ask how much of the MLP's contribution to loss the features account for. The headline figure is 79%, and the paper attaches its own reasons for reading that number cautiously. It also runs the control that matters most to it — dictionary learning on a randomized transformer — to ask whether the features are about the model or about the data.

SUB-CONCEPTS (these render as expandable sections BELOW your page - reference them, do not duplicate them):
  - activation-prediction-scoring | Activation Prediction and Spearman Scoring: Claude predicts activations for 60 nine-token examples from the explanation alone; the score is the Spearman correlation between predicted and true activations.
  - activation-quantization | Quantizing Activations to 0–9: Activations are rounded to integers 0 through 9 before being shown to or predicted by the language model.
  - automated-logit-scoring | Automated Interpretability on Logit Weights: Asking Claude, from the feature's explanation alone, whether an unseen high-logit token is one the feature should predict; features score 74% versus 58% for neurons against a 50% chance baseline.
  - constant-prediction-zero-score | Constant Predictions Score Zero: When Claude predicts the same value for everything — usually all zeros — no correlation exists, and the paper assigns a score of zero.
  - explanation-generation-setup | Explanation Generation Setup: The exact prompt composition used to get a feature explanation out of Claude 2: 49 examples of specified kinds, plus logits, interval labels, and eight worked demonstrations.
  - explanation-length-caveat | Explanation Lengths Caveat: Claude sometimes fails to wrap its explanation in answer tags, so the full chain of thought is used instead — a null result, since it does not change scores.
  - importance-scoring | Importance Scoring: A reweighting that corrects for the non-random sampling of scored examples — and which, in this setting, mostly collapses feature scores toward zero.
    - importance-scoring-degeneracy | Why Importance Scoring Collapses Feature Scores: Because feature densities are around 1e-3 to 1e-6, nearly all the weight lands on random examples where the feature never fires, so predicting zero everywhere scores well.
  - no-activation-leakage | No Leakage of Activation Information: The design constraint that nothing about a feature's activation pattern reaches the prediction step except through the written explanation.

PREREQUISITES:
  - activation-interval | Activation Interval: One of eleven evenly spaced bands between zero and a feature's maximum activation, used to sample examples uniformly across the whole activation spectrum rather than just the top.
  - monosemanticity | Monosemanticity: The property of a unit responding to one coherent thing, so that a single interpretation covers when it fires and what it does.

EVIDENCE ITEMS THAT SHOW THIS (link them as [[item-id]]):
  - fig-4 | Anatomy of a Feature Page: A labelled tour of one page of the paper's published feature browser, which puts four kinds of evidence about a single learned feature side by side: where it fires, what it does to the next-token logits, whether any single neuron matches it, and whether a parallel training run found the same thing. For the feature shown, no neuron correlates with it above 0.09, while a feature from the parallel run correlates at 0.75.
  - fig-5 | The Feature Search Bar: A screenshot of the search strip in the paper's public feature browser, with its four dropdowns opened. It carries no results, so what it establishes is only the shape of the query the authors built for themselves: pick a matching mode, pick which part of a feature's record the query is matched against, pick a sort key over all features in a run, and pick which per-token loss difference is drawn as underlines.
  - fig-6 | Text-First Feature Browser: A second published interface that inverts the usual view: instead of picking a feature and seeing the texts it fires on, you pick a text and see every feature active anywhere in it, ranked, each with a machine-written label. Hovering a token re-ranks the list for that token; hovering a feature paints its activation back onto every token. This is tooling for auditing the decomposition, not evidence for any claim.
  - fig-40 | Autointerp Activation Scores: A language model is asked to write an explanation of a unit from examples where it fires, then to predict that unit's activations on unseen text using nothing but its own explanation. Scored as the rank correlation between predicted and true activations, the autoencoder's features come out at a median of 0.58 and the transformer's MLP neurons at 0.2. The paper reports this as agreement with its separate human scoring: features are easier to explain than neurons.
  - fig-41 | Logit-Weight Scores, Features vs Neurons: Given only a written explanation of a unit, Claude predicts which unseen tokens that unit promotes with 0.74 mean accuracy for autoencoder features and 0.58 for MLP neurons, against a 0.5 chance baseline. The neuron distribution piles up on the chance line while the feature distribution spreads toward 1.0. The "failures" counts in the legend are parsing failures of the scoring harness, not low scores.
  - fig-69 | Pearson vs Spearman Scoring Panel: The paper re-runs its automated interpretability scoring with Pearson correlation alongside the Spearman correlation used throughout the main text, and the two give visibly the same distributions and the same ordering: dictionary-learning features score well above transformer neurons, while features from a randomized model sit awkwardly high. This is a check that the headline gap does not depend on which correlation coefficient was chosen, not a new measurement.
  - fig-72 | Explanation Length Distributions: A prompting bug sometimes let Claude's whole chain of thought stand in as a feature's explanation, producing explanations several hundred tokens long instead of a few dozen. This figure shows that the long tail appears in all three scored populations at similar rates — 19% for neurons, 15% for the randomized model, 13% for the A/1 features — and the appendix reports that splitting scores into long-explanation and short-explanation groups does not change them significantly. It is a caveat check the authors ran, not a result about features.
