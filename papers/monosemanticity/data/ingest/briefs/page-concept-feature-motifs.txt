NAME: Feature motifs

SUMMARY (already shown above your page as the lede - do not repeat it verbatim):
The recurring kinds of features the paper finds: context features, token-in-context features, trigram features, sequence-memorizing features, and features readable as actions.

DRAFT EXPLANATION from the extraction stage (your page replaces this; keep what is right, go deeper):
Rather than catalogue individual features, the paper names the categories that keep appearing. It offers a theoretical reason for the prevalence of the first two: attention heads can largely implement three-point functions with two inputs and an output, while MLP layers are well positioned to implement conjunctions over many tokens — of which context and token-in-context features are the extreme cases. The volume of token-in-context features in particular is described as striking and as not what the authors expected to find in a one-layer model.

THEME IT BELONGS TO: theme-what-the-features-look-like-together | What the features look like together - With thousands of features in hand, the paper stops arguing about individual ones and describes the collection. It sorts them into recurring kinds — features for a whole context, features for one token inside a context, short fixed continuations, memorized phrases — and finds groups that hand off to one another across the token stream like a state machine. Widening the autoencoder does not find new territory but subdivides what was already there, which the paper calls feature splitting and treats as a zoom level rather than a fixed answer. The geometry that comes out of this leads the authors to revise the picture of superposition they started with, and they flag which parts of that revision are still speculation.

SUB-CONCEPTS (these render as expandable sections BELOW your page - reference them, do not duplicate them):
  - action-features | Features as actions: The dual reading of every feature in a one-layer model: it both responds to something and acts to raise the probability of something.
  - context-features | Context features: Features that fire across a whole region of text of a certain kind — DNA sequences, base64 strings, a particular language — rather than on one token type.
  - finite-state-automata-features | Finite state automata: Assemblies of features where one feature raises the probability of tokens that in turn cause another feature to fire on the next step, forming a state machine over generated text.
    - html-feature-automaton | The four-node HTML system: Four A/0 features that hand off to each other to generate valid HTML: open tag, tag name, tag close, whitespace, and back to open tag.
    - mechanistic-anomaly-detection | Mechanistic anomaly detection: The idea of noticing when a model's internal mechanism behaves differently in a specific narrow case.
    - self-exciting-feature-loop | Single-node loop: The simplest case: a feature that increases the probability of tokens which would themselves activate it again.
    - unicode-token-state-machines | Two-node systems from split Unicode characters: Where a script's characters are tokenized as a prefix byte plus a suffix byte, the model alternates between a prefix feature and a suffix feature.
  - memorization-features | Sequence-memorizing features: Features that respond to a specific long phrase and appear to reproduce it, visible only in large dictionaries.
  - phenomenology | Phenomenology: The paper's name for using the feature decomposition to reason about properties of the model, by analogy to phenomenology in physics.
  - token-in-context-features | Token-in-context features: Features that fire on one specific token but only in a particular kind of context — 'the' in mathematics, '<' in HTML.
  - trigram-features | Trigram features: Features that implement short fixed continuations, such as predicting '19' after 'COVID-'.
