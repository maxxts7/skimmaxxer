PAGE FOR CONCEPT: dna-feature
NAME: DNA Feature (A/1/2937)

SUMMARY (already shown above your page as the lede - do not repeat it verbatim):
A feature firing on long uppercase strings of A, T, C and G. Unlike the Arabic case it appears to be the only feature devoted to this context.

DRAFT EXPLANATION from the extraction stage (your page replaces this; keep what is right, go deeper):
A/1/2937 activates on nucleotide sequences. All ten random dataset examples above activation 6.0 are DNA sequences, and its binarized proxy correlation is 0.8. Two things distinguish it from the Arabic case: it is the only feature modeling the DNA context rather than one of a family, and the proxy is less sensitive than the feature — the feature fires on DNA containing spaces, punctuation or missing bases that the strict [ATCG] proxy rejects. It also fires on the prefix 5'- in "5'-TCT", where DNA is about to follow but the prefix itself is not DNA; ablation confirms the feature is helping predict what comes after. Its top logit weights are all nucleotide combinations such as AGT and GCC.

THEME IT BELONGS TO: theme-four-features-up-close | Four features up close - Having a decomposition is not the same as having interpretable features, so the paper picks four — Arabic script, DNA, base64, Hebrew — and tries to establish the same five claims about each. The claims are that the feature fires only in its context, fires whenever that context is present, changes the model's output in a matching way, is not just a neuron in disguise, and turns up again in a separately trained model. The specificity argument leans on a hand-built proxy: a cheap score for whether a string looks like the hypothesized context, computed without reference to the model. The paper says outright that these four were chosen for being easy to analyze, not for being typical, which is why the next theme exists.

PREREQUISITES:
  - dna-proxy | DNA Proxy: A score for "is a DNA sequence", modeling DNA as random strings over [ATCG] and evaluated on groups of at least two tokens.
  - feature-evidence-template | The Five-Claim Feature Template: The fixed set of five claims the paper tries to establish for each individual feature it studies in depth: specificity, sensitivity, downstream effect, non-correspondence to a neuron, and universality.
  - logit-weight | Logit Weight: The vector, one entry per vocabulary token, giving how much a feature's firing pushes up or down each next-token logit.

EVIDENCE ITEMS THAT SHOW THIS (link them as [[item-id]]):
  - fig-20 | DNA Activations Split by Proxy: Every token in a sample of the data is sorted by how strongly the DNA feature A/1/2937 fires on it, and colored by whether a hand-built "is this DNA" score fires on it too. The strong activations are almost entirely DNA and the weak ones are mixed, and across the whole range the feature and the yes/no score reach a Pearson correlation of 0.8.
  - fig-21 | The DNA Feature-Proxy Disagreement Grid: A random-sample grid crossing the DNA feature's activation level against whether the hand-built DNA proxy fires, used to audit the cases where the two disagree. The authors read all 24 disagreements and attribute 22 of them to the proxy's strict ATCG vocabulary rather than to the feature, leaving one genuine miss and one genuine false alarm. It is a hand-judged count of 48 examples, so it supports the claim that the feature is sensitive and specific for DNA rather than measuring it.
  - fig-22 | The DNA Feature's Logit Weights: Plotting how much the DNA feature A/1/2937 pushes each vocabulary token's next-token logit up or down, the paper finds the usual shape: a tall mode of near-zero weights, plus a tiny bump far out in the right tail. Every token in that bump is a short uppercase string of A, T, C and G — 'ATCC', 'GCC', 'AGT', 'TTTT' and so on. What the feature does to the model's predictions therefore matches what makes it fire, and logit weights are never shown to the dictionary learning, so this is independent of how the feature was found.
  - fig-23 | The DNA Feature's Nearest Neuron: The neuron that comes closest to the DNA feature is not a DNA neuron: across its whole activation range, and in random examples drawn from the top of that range, the DNA proxy fires on only a thin sliver of tokens and no nucleotide strings appear. The paper reads this as evidence that dictionary learning found something the neuron basis does not already contain, rather than relabelling an already-clean neuron.
  - fig-24 | The DNA Feature in a Second Model: A separately trained transformer, given its own dictionary learning run, yields a feature that fires on almost exactly the same tokens as the DNA feature (activation correlation 0.92) and pushes up the same nucleotide tokens. Their logit weights agree only weakly overall (0.46), but the disagreement lives in a large near-zero central mode that the paper hypothesizes is interference noise, while the small circled DNA-token mode is shared.
  - fig-43 | Pinning Features to Steer Generation: Holding a single learned feature at a high value while sampling makes the model emit text of exactly the kind that feature normally fires on — Arabic script, DNA, base64, hexadecimal, Hebrew, Han Chinese, or uppercase. Because the autoencoder was fitted only to MLP activations and never to the model's outputs, the paper reads this as evidence that these features are used by the model's computation, not just artifacts of correlations in the data.
  - fig-55 | Single-Node Feature Loops: Four features from the smallest dictionary each raise the probability of exactly the kind of token that would make them fire again one position later, so each one behaves as a one-state machine that keeps re-entering itself. The paper offers this as the simplest case of its "finite state automata" motif. The evidence shown is a list of top-promoted tokens, not a measured transition rate.
