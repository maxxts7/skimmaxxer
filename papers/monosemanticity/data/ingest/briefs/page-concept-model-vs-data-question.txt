NAME: Do Features Tell Us About The Model Or The Data?

SUMMARY (already shown above your page as the lede - do not repeat it verbatim):
The worry that dictionary learning on activations might be recovering correlations in the dataset rather than anything the model computes, and the paper's answers to it.

DRAFT EXPLANATION from the extraction stage (your page replaces this; keep what is right, go deeper):
A model's activations reflect both the dataset's distribution and the way the model transforms it, so dictionary learning on activations mixes the two. Correlations in the data can survive the first part of the model, and the paper concedes it is in theory possible that the features are artifacts of dataset correlations projected into a different space. It gives two answers. First, the randomized-weight model: dictionary learning there yields mostly single-token features and non-single-token features it cannot interpret, so the trained model's activations have richer structure than the token distribution alone. Second, the structural argument: the second half of the model — MLP down-projection and unembedding — is not an input to dictionary learning, so the interpretability of downstream effects must be a property of the model, and the paper checks this three ways with logit weights, ablation, and pinned sampling.

THEME IT BELONGS TO: theme-from-four-features-to-all-of-them | From four features to all of them - Four hand-picked features prove nothing about the population, so the paper turns to measurements over many features and the neurons they are meant to replace. A blinded human rater scores features and neurons on the same rubric; a language model is asked to explain a unit and then predict its activations from that explanation alone; and the reconstruction is spliced back into the transformer to ask how much of the MLP's contribution to loss the features account for. The headline figure is 79%, and the paper attaches its own reasons for reading that number cautiously. It also runs the control that matters most to it — dictionary learning on a randomized transformer — to ask whether the features are about the model or about the data.

  - randomized-transformer | Randomized Transformer Baseline: Dictionary learning run on a one-layer model whose weights have been randomly shuffled, used to ask how much of the features' structure comes from the data rather than the model.
    - randomized-feature-bimodality | Bimodality of Randomized Features: The randomized model's features split into a single-token cluster and a polysemantic cluster; once separated, the real features win on the second.
    - single-token-features | Single Token Features: Features where the same token carries the largest activation in all twenty top-interval examples; abundant in the randomized model and trivially easy to explain and score.
    - weight-shuffling | Weight Shuffling: The randomization method: shuffle the entries within each weight matrix of the trained model rather than resampling them.

PREREQUISITES:
  - dictionary-learning | Dictionary learning: The problem of writing each activation vector as a sparse combination of directions drawn from a fixed, larger-than-necessary set. The paper frames the search for a model's features as exactly this problem.
  - feature-downstream-effects | Feature Downstream Effects: Evidence that a feature causally changes the model's predictions in a way that matches its interpretation, measured three ways: logit weights, ablation, and pinned sampling.
