NAME: Input/output representation

SUMMARY (already shown above your page as the lede - do not repeat it verbatim):
A single token-sequence format that can represent either one span of text or a pair of spans, so one architecture covers every task.

DRAFT EXPLANATION from the extraction stage (your page replaces this; keep what is right, go deeper):
BERT's input is always one token sequence, whether the task supplies one piece of text or two. The sequence begins with [CLS], separates a packed pair with [SEP], and marks which half each token belongs to with a learned segment embedding. Each token's input vector is the sum of its token, segment and position embeddings. This is what lets the same pre-trained model be fine-tuned on classification, entailment, tagging and question answering without architectural surgery.

THEME IT BELONGS TO: theme-what-bert-reads | What BERT reads - One input format has to cover a single text, a sentence pair and a question with its passage. A sequence opens with [CLS], packs one or two spans separated by [SEP], and gives every token a vector that is the sum of three learned embeddings: which token it is, which of the two spans it sits in, and which position it occupies. Two outputs are named here because everything later reads them: C, the final vector at [CLS], and T_i, the final vector at token i. Read this before the pre-training tasks, which are defined over exactly these positions.

  - sentence-pair-packing | Sentence A / sentence B packing: Two spans are concatenated into one sequence, the first labeled A and the second B, so a pair of texts is handled by the same single-sequence model.

  - position-embeddings | Position embeddings: A learned vector per position, added so the model knows token order.

  - final-hidden-vector-ti | T_i, the final vector for token i: The output of the top layer at position $i$, $T_i \in \mathbb{R}^H$, described as that token's contextual representation.
