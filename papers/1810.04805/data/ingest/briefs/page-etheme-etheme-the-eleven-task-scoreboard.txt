NAME: The scoreboard, and how it was assembled

THEME SUMMARY (shown above your page as the lede - do not repeat verbatim):
On the eight scored GLUE tasks both model sizes lead every column, lifting the average by 4.5 points for BERT_BASE and 7.0 for BERT_LARGE. Some of the scoreboard's construction is stated openly: WNLI is dropped because no system beats the majority-class baseline on it, GLUE's own aggregate score therefore differs from the paper's average, and BERT_LARGE fine-tuning was unstable enough on small sets that several restarts were run and the best kept on Dev. Because fine-tuning costs about an hour, the small grid of batch size, learning rate and epochs is searched exhaustively, with selection on Dev since GLUE withholds test labels behind a submission server. SQuAD 1.1 and 2.0 are reported against public leaderboards whose top entries may train on any public data, which is how the TriviaQA pre-fine-tuning is framed — worth 0.1 to 0.4 F1. Ensembling seven models buys 1.4 F1 on SQuAD 1.1, and on SWAG the paper reports 86.3% test accuracy, 27.1 points above the dataset authors' baseline.

The paper says such a search is reasonable precisely because fine-tuning is fast, at most an hour on a single Cloud TPU. If fine-tuning cost what pre-training costs, this protocol would not be affordable.
  e030 [supporting] glue-fine-tuning-protocol (GLUE fine-tuning protocol) --depends-on--> glue-evaluation-server (GLUE evaluation server and hidden test labels) | hidden test labels push tuning to Dev: GLUE withholds test labels and scores only submitted predictions, and the paper reports making a single submission for each model size. Everything else must therefore be settled on the development set. So batch size and epoch count are fixed at 32 and 3 for all tasks, with only the learning rate chosen per task on Dev.

  e126 [supporting] wnli (WNLI (Winograd NLI) and why it is excluded) --contrasts-with--> majority-class-baseline (Majority-class baseline) | no system beats the floor: WNLI is one of GLUE's nine tasks but is left out of the paper's reported results. The stated reason is that the set's construction is problematic. Always predicting the most frequent label is the floor any real system should clear, and on WNLI it is not reliably cleared.
  e127 [minor] glue-score (GLUE leaderboard score) --contrasts-with--> wnli (WNLI (Winograd NLI) and why it is excluded) | official score versus paper's average: Table 1's Average column is not the official GLUE number, because WNLI is excluded from it.   e131 [supporting] triviaqa-augmentation (TriviaQA data augmentation) --contrasts-with--> squad-leaderboard-public-data-rules (SQuAD leaderboard conditions) | extra data to match rivals: The leaderboard entries BERT is compared against have no up-to-date public descriptions and are allowed to train on any public data.   e133 [supporting] ensembling (Ensembling) --contrasts-with--> table-2 (BERT against the SQuAD leaderboard (table-2)) | seven models for 1.4 F1: Table 2 reports a single fine-tuned BERT_LARGE at 91.8 test F1 and a seven-model ensemble at 93.2. The ensemble uses different pre-training checkpoints and fine-tuning seeds, so it costs seven runs rather than one. The paper is explicit that the single model already beats the top leaderboard ensemble, which puts the extra 1.4 F1 in perspective.
