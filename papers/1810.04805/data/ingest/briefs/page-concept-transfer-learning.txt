NAME: Transfer learning

SUMMARY (already shown above your page as the lede - do not repeat it verbatim):
Training a model on one large task or corpus and reusing its parameters on a different, usually smaller, target task.

DRAFT EXPLANATION from the extraction stage (your page replaces this; keep what is right, go deeper):
The paper treats transfer as the organising idea behind the work it reviews: a model trained once on plentiful data supplies representations that a target task has too little labeled data to learn alone. Section 2 splits the sources into unlabeled text and labeled data from large supervised tasks. The conclusion states that recent gains from language model transfer make unsupervised pre-training an integral part of many language understanding systems, and frames the paper's contribution as generalising those findings from deep unidirectional to deep bidirectional architectures.

THEME IT BELONGS TO: theme-pre-training-and-how-it-was-reused | Pre-training and how it was reused - Sets out the practice BERT builds on: train a model on unlabeled text once, then reuse it on a labeled task that has far less data. The paper sorts prior work into two strategies. One keeps the pre-trained model frozen and feeds its vectors into a hand-built architecture as extra features; the other adds a small head and fine-tunes every pre-trained weight. ELMo is the paper's example of the first and OpenAI GPT of the second, and BERT is defined against both, so this comes first.

SUB-CONCEPTS (these render as expandable sections BELOW your page - reference them, do not duplicate them):
  - language-model-pre-training | Language model pre-training: Training a model on a language modeling objective over unlabeled text, then reusing it for downstream NLP tasks.
    - unlabeled-text | Unlabeled text: Plain running text with no human annotation, used as the training signal for objectives that predict text from text.
    - downstream-task | Downstream task: The labeled end task a pre-trained representation is applied to, such as question answering, entailment or tagging.
      - sentence-level-tasks | Sentence-level tasks: Tasks producing one label for the whole input, such as inference, paraphrase detection and sentiment classification.
        - natural-language-inference | Natural language inference: Given a premise and a hypothesis, decide whether the hypothesis is entailed by, contradicts, or is neutral with respect to the premise.
      - token-level-tasks | Token-level tasks: Tasks where the model must produce output at each token, such as named entity recognition and extractive question answering.
        - question-answering | Question answering: Given a question and a passage, produce the answer; in the extractive form used here, mark the passage span that answers it.
        - named-entity-recognition | Named entity recognition: Labeling each token with whether it belongs to a name of a person, organisation, location and so on, and which type.
          - conll-2003-ner | CoNLL-2003 NER: The shared-task dataset used as the standard NER benchmark, and the testbed for BERT's feature-based and masking ablations.
            - tagging-without-crf | Tagging without a CRF layer: NER is formulated as tagging, but the output layer is a plain per-token classifier with no conditional random field on top.
            - first-sub-token-classification | First sub-token as the token representation: When WordPiece splits a word, the first piece's final hidden vector is what the tag classifier reads.
    - transfer-strategies | Feature-based vs. fine-tuning transfer: The paper's taxonomy of the two ways pre-trained representations were applied downstream: as extra input features, or by fine-tuning the whole model.
      - feature-based-approach | Feature-based approach: Keep the pre-trained model fixed and feed its representations into a separate task-specific architecture as extra input features.
        - task-specific-architecture | Task-specific architecture: A model designed by hand for one task, into which pre-trained representations are inserted as features.
        - elmo | ELMo: A feature-based model that extracts context-sensitive word features from separately trained left-to-right and right-to-left language models, concatenating the two directions.
      - fine-tuning-approach | Fine-tuning approach: Add minimal task-specific parameters on top of the pre-trained model and train all pre-trained parameters further on labeled task data.
        - minimal-task-specific-parameters | Minimal task-specific parameters: The design goal that adapting to a new task should add as few new weights as possible.
        - openai-gpt | OpenAI GPT: A fine-tuning approach that pre-trains a left-to-right Transformer language model on unlabeled text, then fine-tunes it on downstream tasks; the paper's main comparison point.
    - contextual-representations | Contextual representations: Token vectors that depend on the surrounding sentence, so the same word form gets different vectors in different sentences.
      - context2vec | context2vec: A model that learns contextual representations by predicting a single word from both its left and right context using LSTMs.
    - pre-trained-word-embeddings | Pre-trained word embeddings: Word vectors learned once from a large unlabeled corpus and reused across tasks, rather than learned per task.
      - word-embeddings | Word embeddings: Dense vectors representing words, learned so that distributional similarity shows up as vector similarity.
      - sentence-embeddings | Sentence embeddings: Fixed-size vectors representing whole sentences, pre-trained from unlabeled text the way word vectors are.
  - supervised-transfer-learning | Transfer from supervised data: Using a model trained on a large labeled task as the starting point for other tasks, as an alternative to pre-training on unlabeled text.
  - low-resource-tasks | Low-resource tasks: Tasks with too little labeled data to train a deep model from scratch.
