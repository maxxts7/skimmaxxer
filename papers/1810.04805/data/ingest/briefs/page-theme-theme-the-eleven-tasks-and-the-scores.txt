NAME: The eleven tasks and the scores

THEME SUMMARY (shown above your page as the lede - do not repeat verbatim):
The evaluation itself: eleven tasks, each a small output layer on the same pre-trained encoder. GLUE supplies the sentence and sentence-pair tasks, SQuAD 1.1 and 2.0 the span extraction, and SWAG a four-way completion. Each gets its own head — a linear layer on C for GLUE, a start vector and an end vector for spans, one scoring vector over four packed sequences for SWAG. Gains are reported as absolute point differences over the previous best, and this theme walks each benchmark and what BERT scored on it.

EVIDENCE ITEMS RELATED TO THIS THEME (link as [[item-id]]):
  - fig-1 | The Same Stack, Twice: The figure claims that pre-training and fine-tuning use one and the same network: an identical token-in, vector-out Transformer encoder appears in both panels, and the only thing that changes between them is the thin output layer bolted on top. The dotted arrows carry every pre-trained weight across to initialize the task model, so a downstream task inherits the whole network rather than a set of embeddings.
  - table-1 | The GLUE test scoreboard: On the eight scored GLUE tasks, both BERT sizes beat every prior system in every column, lifting the average by 4.5 points (BERT_BASE) and 7.0 points (BERT_LARGE) over OpenAI GPT, with a 4.6-point gain on MNLI. Because BERT_BASE is the same size as GPT, the paper reads the gap as evidence for bidirectional pre-training rather than for extra capacity.
  - table-2 | BERT against the SQuAD leaderboard: On SQuAD 1.1 span extraction, a fine-tuned BERT_LARGE ensemble reaches 93.2 test F1 and a single fine-tuned BERT_LARGE reaches 91.8, which the paper reports as +1.5 F1 and +1.3 F1 over the top leaderboard system of the day. Both figures come with an asterisk the paper states itself: the leaderboard entries may train on any public data, so BERT is first fine-tuned on TriviaQA to match, and dropping that extra data costs only 0.1-0.4 points.
  - table-3 | SQuAD 2.0 Leaderboard Comparison: On SQuAD 2.0, where some questions have no answer in the passage, a single fine-tuned BERT_LARGE reaches 83.1 Test F1 against 78.0 for the best prior entry the authors count — a +5.1 F1 gap, on a task the paper handles by adding only two vectors and one threshold. It still sits about 6 F1 below the reported human number, and the comparison is restricted to systems that do not already use BERT inside them.
  - table-4 | The SWAG Commonsense Scoreboard: On SWAG's four-way sentence-completion task, BERT_LARGE reaches 86.3% test accuracy, which the paper reports as +27.1 points over the dataset authors' own ESIM+ELMo baseline and +8.3 points over OpenAI GPT. That figure also sits above the 85.0 scored by a single human expert, though the dagger footnote says the human numbers come from only 100 samples, so the human comparison rests on much thinner ground than the model comparisons.
  - table-5 | Pre-training Task Ablation: Holding architecture, data and fine-tuning fixed, the table charges each drop in score to one removed piece of the pre-training recipe. Dropping next sentence prediction costs a little; replacing the masked LM with a left-to-right LM costs much more, above all on SQuAD (88.5 to 77.8 F1), and bolting a BiLSTM onto the left-to-right model repairs only part of that gap while making the GLUE numbers slightly worse.
  - table-6 | The Model-Size Ladder: Six separately pre-trained BERT models, from 3 layers up to 24, are lined up smallest to largest: held-out masked-LM perplexity falls at every step (5.84 to 3.23) while accuracy on MNLI-m, MRPC and SST-2 rises at every step. The paper reads this as evidence that scaling keeps paying off past sizes already considered large, and — its actual point — that the gains reach a task as small as MRPC, which has only 3,600 training examples.
  - fig-4 | Four task shapes, one encoder: Four families of downstream task are drawn as four copies of the same diagram, differing only in what is packed into the input sequence and which output vectors an arrow is attached to. The paper uses this to show that adapting BERT to a task means plugging in task-specific inputs and one extra output layer, not redesigning the model.
  - fig-5 | MLM vs. Left-to-Right Over a Million Steps: Fine-tuning from progressively later pre-training checkpoints shows that MNLI accuracy is still climbing at 1,000,000 steps, so BERT's long pre-training run is not wasted. It also shows that the masked LM objective is behind a left-to-right objective at the very first checkpoints, overtakes it before 100k steps, and finishes roughly two points ahead.
  - table-8 | The masking mixture ablation: Six BERT pre-training runs that differ only in what happens to a token once it has been selected for prediction. Changing the mixture barely moves the fine-tuned scores, but pre-training with [MASK] alone costs 0.9 F1 on NER when BERT is frozen and used as a feature extractor. That single column is the paper's evidence for keeping the 80/10/10 mixture rather than always inserting [MASK].
  - eq-classification-loss | The GLUE Classification Head: This inline expression is the whole task-specific model BERT adds for a GLUE sentence-classification task: take the final hidden vector at the [CLS] position, multiply it by one new weight matrix to get one score per label, and train with ordinary cross-entropy. The paper's point in printing it is how little there is — a single $K \times H$ matrix is the only parameter matrix fine-tuning introduces.
  - eq-span-start-probability | The start-position softmax: This is the whole task-specific output layer BERT adds for extractive question answering: one learned vector $S$ is dotted with each passage token's final hidden vector, and a softmax over those scores gives a probability distribution over where the answer span starts. A second vector $E$ does the same for the end, and training maximizes the summed log-likelihood of the correct start and end positions.
  - eq-span-score | The additive span score: A candidate answer running from token $i$ to token $j$ is scored by adding its start score $S{\cdot}T_i$ to its end score $E{\cdot}T_j$, and the prediction is whichever pair with $j \geq i$ scores highest. The whole answer-selection machinery is two dot products and a comparison, with no module that looks at the span as a unit.
  - eq-null-answer-threshold | The Null-Answer Threshold Rule: This is the prediction-time rule BERT uses on SQuAD 2.0, where a question may have no answer. It scores "no answer" as an ordinary span that starts and ends at [CLS], compares it against the best real span, and only outputs a real span when that span wins by more than a constant tau, which is fitted on the dev set.
