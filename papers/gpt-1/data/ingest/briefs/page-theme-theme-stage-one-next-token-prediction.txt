NAME: Stage One: Predicting the Next Token

THEME SUMMARY (shown above your page as the lede - do not repeat verbatim):
Stage one trains on a single loss: the log-probability the model assigns each token given a window of preceding tokens, summed over the corpus. The window here is 512 contiguous tokens, which is what lets a prediction condition on material several sentences back. The network is a stack of transformer blocks used as a decoder alone, with self-attention masked so each position sees only itself and its past, learned position vectors rather than fixed sinusoids, and an output layer that reuses the token embedding matrix transposed. This chapter also fixes the exact sizes trained, and closes with the claim the paper makes about what such training leaves behind.

EDGES BETWEEN MEMBERS OF THIS THEME:
  [load-bearing] language-modeling-objective --depends-on--> masked-self-attention | next-token loss needs future hidden: The loss asks the model to predict each token from the tokens before it, and it does this at every position at once. Without the mask, a position could attend to the token it is being asked to predict, and the objective would be solved by copying rather than by learning. The mask is what makes a single forward pass over a 512-token sequence produce 512 honest predictions.
  [supporting] output-softmax-tied-embeddings --depends-on--> token-embedding-matrix | output layer reuses input embeddings: There is no separate output projection in equation 2. The top block's states are multiplied by the transpose of the same matrix $W_e$ that turned tokens into vectors on the way in, and softmaxed. Reading the output head means reading the embedding table twice, once forwards and once backwards.
  [supporting] input-representation-h0 --depends-on--> learned-position-embeddings | attention needs position injected: Self-attention sees a set of vectors, not an ordered sequence, so order has to be added to the input rather than inferred from it. Layer zero is $h_0 = UW_e + W_p$: the token vectors with a position vector added to each slot. Take $W_p$ away and the model cannot tell which token came first.
  [supporting] context-window-512-tokens --depends-on--> learned-position-embeddings | trained table fixes maximum length: The paper trains $W_p$ rather than using the original transformer's fixed sinusoids. A trained table has one row per slot, so the number of rows is the longest context the model can ever be given. The 512-token window is therefore a size in the parameter table, not a setting that can be raised at test time.
  [minor] twelve-attention-heads --depends-on--> hidden-state-dimension-768 | heads split the 768 dimensions: The twelve heads do not each get their own 768 dimensions; they divide the state between them. 768 divided by 12 gives each head a 64-dimensional subspace to attend in. Changing the state size or the head count changes the other, unless the per-head width is allowed to move.
  [load-bearing] masked-self-attention --instance-of--> language-modeling-objective | architecture realizing left-context conditioning: L1 conditions each token only on the tokens before it. Masking the attention so a position can see itself and earlier positions but never later ones is the architectural realization of that constraint. Without the mask the model could read the token it is asked to predict, and the objective would be trivial.
  [minor] twelve-attention-heads --instance-of--> masked-self-attention | twelve heads of 64 dimensions: Masked self-attention is the mechanism; the head count is its concrete setting here. Each layer splits its 768-dimensional state across twelve heads, so each head attends in a 64-dimensional subspace. Twelve heads and twelve layers happen to match, but they are separate dials.
  [minor] position-wise-feedforward-3072 --instance-of--> multi-layer-transformer-decoder | feed-forward width in this model: Each block in the stack ends with a position-wise feed-forward sublayer, and this is the size it was given. The layer expands each 768-dimensional vector to 3072 dimensions and projects it back, a four-fold widening. That is the concrete setting of a slot the general architecture leaves open.

EVIDENCE ITEMS RELATED TO THIS THEME (link as [[item-id]]):
  - fig-1 | One Stack, Four Input Shapes: The figure shows that a single decoder-only transformer, pre-trained once, serves every task in the paper: the left panel draws the block that is repeated twelve times and the two heads that sit on it, and the right panel shows that adapting to a new task means rewriting its input as one token sequence rather than redesigning the network. The only task-specific machinery is the added linear layer and the special tokens marking where the parts of an input begin and end.
  - fig-2 | Layer Transfer and Zero-Shot Growth: Two diagnostics for why the recipe works. The left panel says every pre-trained layer carries transferable value: dev accuracy on RACE and MultiNLI rises steadily as more of the twelve-layer stack is carried into fine-tuning, up to about 9% on MultiNLI for full transfer. The right panel says the pre-trained language model is already learning task-relevant behaviour before any fine-tuning: heuristic zero-shot scores on four tasks climb steadily across pre-training, and do so more smoothly for the transformer than for an LSTM trained the same way.
  - table-5 | Three Ablations Against the Full Model: Removing pre-training costs the most by far (14.8 average points), swapping the transformer for an LSTM costs 5.6, and dropping the auxiliary language modelling loss during fine-tuning actually gains 0.3 on average — helping only on the larger datasets (QQP and the two NLI sets) and hurting on the smaller ones.
  - eq-lm-objective | The Pre-Training Likelihood $L_1$: This is the entire training signal for stage one: over a corpus of unlabelled tokens, sum the log-probability the network assigns to each token given the $k$ tokens immediately before it, and adjust the network's parameters $\Theta$ to make that sum as large as possible. No labels, no task, and one training term per token position.
  - eq-decoder-stack | The Decoder Stack, Input to Output Distribution: Equation 2 spells out the whole pre-training network in three lines: embed the context tokens and their positions, push the result through $n$ identical transformer blocks, then project the top layer back through the transposed token embedding matrix and softmax it into a distribution over the next token. The same matrix $W_e$ does the work at both ends, so no separate output vocabulary matrix is introduced.
  - eq-task-head | The Linear Task Head on the Last Token: Equation 3 is the entire task-specific classifier: take the final transformer block's activation at the last input token, multiply it by one matrix $W_y$, and softmax the result into a distribution over the task's labels. The paper states that $W_y$ (plus delimiter-token embeddings) is the only new parameter it adds when moving the pre-trained model to a new task.
  - eq-supervised-objective | Supervised Fine-Tuning Objective $L_2$: Equation 4 is the loss used in the second training stage: over a target task's labelled dataset $\mathcal{C}$, sum the log-probability the model assigns to each instance's correct label. It is ordinary maximum-likelihood classification training, written so that the only thing separating one task from another is which labelled set $\mathcal{C}$ you plug in.
  - eq-combined-objective | The Combined Fine-Tuning Objective: During fine-tuning the paper does not drop the language modelling loss; it keeps optimizing it alongside the classification loss, scaled by a weight $\lambda$, and computes it on the labelled task data rather than on the pre-training corpus. The paper reports this helped by improving generalization and speeding convergence, and its own ablation later qualifies that: the gain shows up on larger datasets, not on smaller ones.
